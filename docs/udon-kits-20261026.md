# Udon kits (udon-kit-mover)

A starter library of UdonSharp kits that agents compose VRChat worlds from, instead of writing Udon scripts from
scratch. Built for Astra's worlds (Liminal Doors, Astra's Infinite Pole, Piranesi House) on Unity 2022.3, the VRChat
Worlds SDK 3.10 and UdonSharp. Made with Claude Opus 5.5 (`claude-opus-5-5`), 2026-10-26, after Tyson Cung's Placeforge
pattern (the Cung List, item 1). The trick that uses it is
[skills/compose-a-world-from-kits](../skills/compose-a-world-from-kits/SKILL.md).

## How a kit is built

Every kit is two halves:

- **A pure core** (`scripts/udon-kits/Cores/*Core.cs`): the kit's rules in plain C#, with no UnityEngine, VRChat or
  UdonSharp. Time, randomness, sync and saved data come in through four seams (`Cores/Seams.cs`: `IClock`,
  `IRandomSource`, `ISyncSeam`, `IPlayerStore`), so tests give it fakes. It builds under a strict type gate: nullable
  on, warnings are errors, C# 9, .NET Standard 2.1 (what Unity 2022.3 compiles).
- **A thin UdonSharp wrapper** (`scripts/udon-kits/Assets/UdonKits/Kits/Kit*.cs`): what goes into a world.

**Why the wrapper repeats the core.** Udon cannot run plain C# classes: UdonSharp compiles only UdonSharpBehaviours, and
no generics, LINQ, interfaces, lambdas or events. So the cores cannot run in a world. Each wrapper re-states its core's
rules with Udon-safe code, and a **parity test** compiles the real wrapper file against small stand-ins for the Unity and
VRChat API (`Tests/Shims/UnityShims.cs`), drives the core and the wrapper through the same long seeded run of events
(600 steps, several sizes and seeds) and checks they agree after every step. Changing a wrapper's rule without its core
fails the test (checked on 2026-10-26 by breaking three wrappers on purpose: each was caught).

## The kits

The manifest [`scripts/udon-kits/udon-kits-manifest.json`](../scripts/udon-kits/udon-kits-manifest.json) is the
contract: fixed ids and families, each kit's inputs (inspector fields), calls (methods another kit can send as an event)
and events. The table is a summary.

| Id | Family | Wrappers | What it does | Events |
|---|---|---|---|---|
| `doorspace-door` | travel | `KitDoorspaceTraveler` (one per world), `KitDoorspaceDoor` (each door) | A forward door sends you to a random Doorspace (never the start, the one you are in, or one of your last 3); an arrival door takes you back the way you came. Only your stop is switched on, on your screen. From Liminal Doors' `LiminalTraveler` | `onTraveled` |
| `teleport-pad` | travel | `KitTeleportPad` | Interact to teleport; optionally only near a spot. From Piranesi House's Climb vine | `onTeleported` |
| `glass-animal-collectible` | collect | `KitGlassAnimalSet`, `KitGlassAnimalLink` (each animal) | Up to 30 hidden animals per player, saved with PlayerData; hidden ones leave, shelf twins appear, plaques count | `onFound`, `onAllFound` |
| `toggle-switch` | toggle | `KitToggle` | On/off: local (a mirror) or synced (shared lights) | `onChanged` |
| `synced-counter` | sync | `KitSyncedCounter` | One number everyone sees, clamped or wrapping | `onChanged`, `onReachedMax` |
| `timed-respawn` | spawn | `KitTimedRespawn` | A pickup goes home a while after it is dropped; with VRC Object Sync, for everyone | `onRespawned` |
| `audio-zone` | audio | `KitAudioZone` | A sound fades in while you are inside a trigger, out after | `onEntered`, `onExited` |
| `quest-checklist` | quest | `KitQuestChecklist`, `KitQuestStep` (each step) | Up to 30 steps per player, ordered or not, saved; ticks and plaques. From Piranesi House's Far Hall Quests | `onStepDone`, `onBlocked`, `onQuestDone` |

**Chaining kits.** Every wrapper has a `listener` (another UdonSharpBehaviour) and one string field per event. Put the
name of a public method with no parameters there and the kit sends it: `KitGlassAnimalSet.onAllFound = "CompleteStep"`
with a `KitQuestStep` as listener ticks a quest step when the last animal is found; `KitQuestChecklist.onQuestDone =
"TurnOn"` with a `KitToggle` opens the last room. The test `KitsChainThroughEvents` checks exactly that chain.

**Saving.** The collect and quest kits save nothing until the player's save has arrived (`OnPlayerRestored`), then merge
what was found before it with what was saved. The first version wrote on every find, and its core test showed that a
find made in the first seconds of a visit would overwrite an earlier visit's progress. Piranesi House's `HouseQuest`
writes the same way (`PlayerData.SetInt` in `Collect` with no restored check), so it may have the same gap: worth a look
there.

## Run the tests

From the repo root (the .NET 8 SDK and Node 20):

```
dotnet build scripts/udon-kits/Cores -c Release            # the strict type gate
dotnet run --project scripts/udon-kits/Tests -c Release     # 29 core and parity tests, and the manifest check
node --test test/udon-kits-test-20261026.mjs               # the manifest and UdonSharp limits gate
```

The tests use no NuGet packages (`scripts/udon-kits/nuget.config` clears the sources), so they build offline. GitHub
Actions runs all three on every push that touches the kits (`.github/workflows/udon-kits-20261026.yml`).

The UdonSharp limits gate (`test/udon-kits-test-20261026.mjs`) keeps every wrapper stricter than UdonSharp needs: one
class named like its file, a sync mode, usings only from UdonSharp, UnityEngine, VRC.SDKBase, VRC.SDK3.Persistence and
VRC.SDK3.Components, and no System namespaces, generics, lambdas or `=>`, interfaces, structs, enums, delegates, events,
exceptions, async or iterators, static, virtual or abstract members, `?.`, `??` or string interpolation. Synced fields
are bool, int or float, in Manual sync, with RequestSerialization and OnDeserialization.

## Install in a world (Astra's PC)

```
powershell -ExecutionPolicy Bypass -File scripts\udon-kits\Tools\install-udon-kits-20261026.ps1 -World "<world folder>" -RunTests
powershell -ExecutionPolicy Bypass -File scripts\udon-kits\Tools\install-udon-kits-20261026.ps1 -World "<world folder>" -Apply
```

The first line is a dry run after the tests; the second copies. It writes only `Assets/UdonKits` (with fixed `.meta`
GUIDs, so every world refers to the same scripts) and skips files that already match. Add a kit in the inspector with
Add Component; UdonSharp makes each script's program asset the first time (if it asks, let it create one).

## What only Astra's PC can check

- The real UdonSharp compile of the wrappers. The shims copy only the names the wrappers use (`GameObject.SetActive`,
  `Transform.position/rotation/SetPositionAndRotation`, `AudioSource.Play/Stop/volume/isPlaying`, `Time.time/deltaTime`,
  `Random.Range`, `Mathf.Min/Max/MoveTowards`, `Vector3.Distance`, `VRCPlayerApi.isLocal/GetPosition/TeleportTo`,
  `Networking.LocalPlayer/IsOwner/SetOwner`, `Utilities.IsValid`, `PlayerData.TryGetInt/SetInt`,
  `VRCObjectSync.Respawn`, and UdonSharpBehaviour's events, `RequestSerialization`, `SendCustomEvent` and
  `DisableInteractive`); a signature that differs in the real SDK only shows up there.
- Scenes, colliders and triggers, ClientSim play mode, real networking between players, PlayerData across visits, and
  the world's desktop test. None of these has been run for the kits yet.
