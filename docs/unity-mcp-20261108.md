# MCP for Unity: Claude and Codex inside the open Unity editor

By Astra. Set up with Claude Opus 5.5 (claude-opus-5-5), 2026-11-08.

MCP (Model Context Protocol) is a plug that lets an assistant work inside a program. With MCP for Unity, Claude Code
and Codex can read the open scene, add and change objects, edit scripts and run tests in the Unity editor, instead of
leaving jobs in a project's agent queue.

## Which one, and why (Astra, 2026-11-08: "All recommended")

| Question | Answer |
| --- | --- |
| Which Unity MCP | **MCP for Unity** by Coplay (free, MIT, `com.coplaydev.unity-mcp`), for Unity 2021.3 to 6. Unity's own MCP (in the AI Assistant package) needs Unity 6 and a Unity AI plan; VRChat projects are on 2022.3.22f1, so it can't run in them. |
| Which project first | **Liminal Doors** (`D:\personal-files\unity\VRChatProjects\liminal-doors`). Poppy stays out. |
| uv on the PC | **Yes**, installed with `winget install astral-sh.uv`. MCP for Unity's small Python helper runs through it. |
| How Unity Unicorn shows it | A **3rd party pill** in L1, planned until it is checked with Unity open, and this doc. |

## What is set up

1. **uv** on the Desktop PC (winget, 2026-11-08). Remove it from Settings > Apps.
2. **Liminal Doors** `Packages/manifest.json`: `"com.coplaydev.unity-mcp": "10.3.0"` from the OpenUPM registry
   (`scopedRegistries`, scope `com.coplaydev`). The git address (`https://github.com/CoplayDev/unity-mcp.git?path=/MCPForUnity`)
   fails on D: with "fatal: not in a git directory", so use OpenUPM in every project. Unity resolved the package once
   (`Library/PackageCache/com.coplaydev.unity-mcp@10.3.0`) with no compile errors.
3. **Claude Code:** `UnityMCP` in the user settings (`~/.claude.json`, `mcpServers`), HTTP, on this PC only.
   Backup of the file before: `~/.claude.json.before-unity-mcp-20261108`.
4. **Codex:** `[mcp_servers.UnityMCP]` in `~/.codex/config.toml`. Backup: `config.toml.before-unity-mcp-20261108`.

The address is on this PC only and stays out of public files (hub rule). It answers only while a Unity project with the
package is open, so a chat started while Unity is closed shows UnityMCP as not connected; that is expected.
